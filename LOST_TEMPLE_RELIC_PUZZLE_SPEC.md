# Lost Temple — механика сборки реликвии

## 1. Назначение механики

После прохождения всех пяти языковых испытаний игрок попадает в зал древнего заброшенного храма.

В зале необходимо восстановить реликвию, собрав пазл из **5 фрагментов**. Источником изображения реликвии является файл:

```text
2.png
```

После полной сборки пазла квест Lost Temple считается завершённым, достижение сохраняется, а игрок получает возможность вернуться на главную страницу.

## 2. Переход в зал реликвии

После правильного выполнения пятого языкового задания показать сообщение:

> **THE RELIC CHAMBER IS OPEN**

Затем проиграть короткую переходную анимацию:

1. древние каменные двери начинают светиться;
2. створки открываются;
3. из зала появляется золотой или зелёный свет;
4. экран переходит в сцену **Relic Chamber**.

## 3. Оформление Relic Chamber

Сцена должна выглядеть как зал древнего заброшенного храма:

- каменные стены и колонны;
- разрушенные статуи;
- корни, лианы и мох;
- тёмное атмосферное освещение;
- центральный алтарь или постамент;
- золотые и зелёные источники света;
- отдельная хорошо различимая область сборки пазла.

Заголовок:

> **RESTORE THE ANCIENT RELIC**

Инструкция:

> **The relic has been broken into five pieces. Place every fragment in its correct position.**

## 4. Подготовка изображения

Перед использованием необходимо удалить белый фон изображения `2.png` и сохранить прозрачную версию реликвии:

```text
assets/relic-transparent.png
```

Прозрачная версия используется:

- для пяти игровых фрагментов;
- для силуэта в области сборки;
- для показа готовой реликвии после завершения пазла.

Нельзя заменять части реликвии абстрактными ромбами, иконками или одноцветными блоками. На каждом фрагменте должна быть видна соответствующая часть исходного изображения.

## 5. Разделение на фрагменты

Реликвия разделяется ровно на **5 частей**.

Требования:

- все части вместе должны точно восстанавливать исходную реликвию;
- у каждого фрагмента должна быть уникальная правильная позиция;
- границы могут иметь форму пазловых выступов, вырезов или неровных каменных сколов;
- части не должны закрывать друг друга в начальном состоянии;
- порядок частей перемешивается при каждом запуске сцены;
- начальная позиция фрагмента не должна совпадать с правильной.

Допустимые способы реализации:

- CSS `background-image` и `background-position`;
- CSS `clip-path`;
- Canvas;
- заранее подготовленные PNG-маски.

## 6. Силуэт готовой реликвии

В центре сцены необходимо показать силуэт целой реликвии, куда игрок будет устанавливать фрагменты.

Силуэт должен:

- повторять точную форму `assets/relic-transparent.png`;
- быть достаточно заметным на фоне храма;
- иметь золотистый оттенок;
- быть полупрозрачным, чтобы не выглядеть уже собранной реликвией;
- содержать пять визуальных зон установки;
- иметь мягкое золотое свечение по контуру.

Рекомендуемые параметры оформления:

```css
opacity: 0.3–0.45;
filter: sepia(1) saturate(2.5) brightness(0.8);
```

Над силуэтом можно показать подпись:

> **RELIC SILHOUETTE**

## 7. Внешний вид фрагментов

Фрагменты должны быть хорошо заметны на тёмном фоне.

Для каждого фрагмента использовать:

- повышенную яркость;
- насыщенный золотой цвет;
- тонкий светлый контур;
- золотое внешнее свечение;
- тёмную объёмную тень;
- усиление свечения при наведении и перетаскивании.

Рекомендуемая визуальная логика:

| Состояние | Оформление |
|---|---|
| Обычное | Золотой контур и мягкое свечение |
| Наведение | Повышенная яркость и сильное золотое свечение |
| Перетаскивание | Максимальная яркость, увеличенная тень |
| Неправильная позиция | Короткое красное свечение или вибрация |
| Правильная позиция | Зелёно-золотое свечение |
| Закреплён | Заблокирован от перемещения |

## 8. Управление

Пазл должен поддерживать:

- перетаскивание мышью;
- Pointer Events;
- сенсорное управление на телефонах и планшетах;
- клавиатуру: выбор фрагмента и установка через `Enter` или `Space`.

Во время перетаскивания необходимо отключить стандартное прокручивание страницы внутри игровой области:

```css
touch-action: none;
```

## 9. Начальное размещение

### На широком экране

- силуэт находится в центре;
- фрагменты располагаются слева и справа от него;
- части не перекрывают силуэт полностью;
- между фрагментами остаётся достаточно места для захвата.

### На мобильном экране

- силуэт располагается сверху;
- перемешанные части располагаются ниже;
- игровая область увеличивается по высоте;
- ширина фрагментов адаптируется под экран.

## 10. Перетаскивание

1. Игрок нажимает на фрагмент.
2. Фрагмент переходит поверх остальных элементов.
3. Игрок перемещает его к силуэту.
4. При отпускании система рассчитывает расстояние до правильной позиции.
5. Если расстояние меньше заданного порога, фрагмент считается установленным.
6. Если расстояние больше порога, размещение считается неправильным.

Порог примагничивания должен зависеть от размера области сборки, чтобы механика одинаково работала на разных экранах.

Пример:

```javascript
const snapDistance = Math.max(65, boardWidth * 0.24);
```

## 11. Правильная установка

При правильном размещении:

1. фрагмент автоматически перемещается в точные координаты;
2. появляется зелёно-золотое свечение;
3. проигрывается короткий звуковой эффект;
4. фрагмент блокируется от дальнейшего перемещения;
5. счётчик увеличивается на единицу.

Сообщение:

> **Fragment secured. 3 remaining.**

## 12. Неправильная установка

При неправильном размещении:

- фрагмент не закрепляется;
- можно оставить его в месте отпускания или вернуть в исходную область;
- показать короткую вибрацию;
- добавить красное свечение;
- не отнимать жизнь;
- не сбрасывать уже установленные части;
- не перезапускать пазл.

Сообщение:

> **That fragment does not belong there. Try another position.**

## 13. Прогресс

В верхней части сцены показать текст:

```text
Relic puzzle: 0 / 5
```

Дополнительный визуальный индикатор:

```text
◇ ◇ ◇ ◇ ◇
◆ ◆ ◆ ◇ ◇
```

Прогресс обновляется только после правильной установки части.

## 14. Завершение пазла

После установки пятого фрагмента:

1. заблокировать все части;
2. скрыть линии между зонами;
3. заменить пазловые части цельным изображением `assets/relic-transparent.png`;
4. добавить яркое золотое и зелёное свечение;
5. проиграть короткую анимацию восстановления;
6. показать сообщение о завершении.

Заголовок:

> **RELIC RESTORED**

Текст:

> **You have recovered the Lost Temple Relic.**

## 15. Сохранение результата

После завершения пазла сохранить:

```javascript
localStorage.setItem("lostTempleCompleted", "true");
localStorage.setItem("lostTempleRelicCollected", "true");
```

Также добавить достижение Lost Temple в общий список:

```javascript
const achievements = JSON.parse(
  localStorage.getItem("expeditionAchievements") || "[]"
);

if (!achievements.includes("temple")) {
  achievements.push("temple");
}

localStorage.setItem(
  "expeditionAchievements",
  JSON.stringify(achievements)
);
```

Повторное прохождение не должно удалять ранее полученную реликвию.

## 16. Возвращение на главную

Кнопка возврата становится доступна только после полной сборки пазла:

> **RETURN TO THE JUNGLE**

или:

> **BACK TO QUEST MAP**

При нажатии игрок возвращается на главную страницу витрины к карте или разделу достижений.

## 17. Критерии готовности

- [ ] Используется реликвия из `2.png`.
- [ ] Подготовлена прозрачная версия `assets/relic-transparent.png`.
- [ ] Реликвия разделена ровно на пять частей.
- [ ] Каждый фрагмент содержит часть исходного изображения.
- [ ] Фрагменты хорошо видны и имеют золотое свечение.
- [ ] В центре показан точный силуэт готовой реликвии.
- [ ] Фрагменты перемешиваются при каждом запуске.
- [ ] Реализовано управление мышью и касанием.
- [ ] Клавиатура позволяет установить выбранный фрагмент.
- [ ] Правильная часть примагничивается к своей позиции.
- [ ] Установленная часть блокируется.
- [ ] Неправильная установка не сбрасывает прогресс.
- [ ] На экране отображается прогресс `0 / 5`.
- [ ] После установки пятой части показывается цельная реликвия.
- [ ] Результат сохраняется в `localStorage`.
- [ ] После завершения доступно возвращение на главную страницу.
