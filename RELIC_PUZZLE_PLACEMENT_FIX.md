# Lost Temple — исправление установки фрагментов пазла

## Проблема

Видимая часть фрагмента реликвии формируется через `clip-path`, но предыдущая проверка размещения опиралась преимущественно на координаты прямоугольного DOM-элемента.

Из-за этого возникала ситуация:

- изображение фрагмента визуально накладывалось на полупрозрачный силуэт;
- игрок отпускал часть рядом с правильной областью;
- координаты прямоугольника не проходили точную проверку;
- игра показывала сообщение `That fragment does not belong there`.

## Требуемое поведение

Фрагменты можно устанавливать **в любом порядке**.

Игрок должен перенести выбранную часть на полупрозрачный силуэт реликвии. Если фрагмент достаточно перекрывает силуэт или указатель отпущен рядом с ним, система автоматически перемещает часть в её собственную правильную позицию.

Игроку не нужно вручную искать точный внутренний слот или попиксельно совмещать края изображения.

## Проверка правильного размещения

Размещение принимается, если выполняется хотя бы одно условие:

1. указатель мыши или палец отпущен внутри расширенной области силуэта;
2. видимая рамка фрагмента пересекает общую область реликвии минимум на 4%;
3. фрагмент пересекает свой точный слот минимум на 12%;
4. центр фрагмента находится рядом с общим силуэтом;
5. координаты фрагмента находятся в допустимом расстоянии от точной позиции.

Пример проверки точки отпускания:

```javascript
const boardRect = board.getBoundingClientRect();
const pointerMargin = Math.max(70, boardRect.width * 0.4);

const pointerNearSilhouette =
  pointerEvent.clientX >= boardRect.left - pointerMargin &&
  pointerEvent.clientX <= boardRect.right + pointerMargin &&
  pointerEvent.clientY >= boardRect.top - pointerMargin &&
  pointerEvent.clientY <= boardRect.bottom + pointerMargin;
```

После принятия фрагмент автоматически устанавливается в координаты, соответствующие его индексу. Порядок ранее установленных частей не влияет на проверку.

## Индикация правильной установки

После правильного размещения фрагмент:

- примагничивается к точной позиции;
- блокируется от дальнейшего перемещения;
- получает яркий зелёный контур;
- подсвечивается зелёным свечением;
- кратко увеличивается во время анимации фиксации;
- увеличивает счётчик `Relic puzzle: N / 5`.

Рекомендуемый стиль:

```css
.puzzle-piece.placed {
  background-color: rgba(34, 190, 66, 0.34);
  background-blend-mode: color-dodge;
  outline: 2px solid #79f06b;
  filter:
    saturate(1.55)
    brightness(1.15)
    drop-shadow(0 0 5px #74ff61)
    drop-shadow(0 0 16px rgba(75, 255, 83, 0.95));
}
```

## Индикация неправильного размещения

Ошибка показывается только тогда, когда фрагмент отпущен далеко от всего силуэта.

При ошибке:

- часть остаётся доступной для перемещения;
- появляется краткое красное свечение;
- ранее установленные части не сбрасываются;
- порядок частей не меняется;
- игрок не теряет жизнь.

## Защита от кеширования

К CSS и JavaScript квеста необходимо добавить версию:

```html
<link rel="stylesheet" href="lost-temple.css?v=4">
<script src="lost-temple-data.js?v=4"></script>
<script src="lost-temple.js?v=4"></script>
```

Это заставляет браузер загрузить исправленную логику вместо ранее закешированной версии.

## Критерии готовности

- [ ] Части можно устанавливать в любом порядке.
- [ ] Достаточно наложить фрагмент на любую часть силуэта.
- [ ] Не требуется точное ручное совмещение с внутренним слотом.
- [ ] Принятый фрагмент автоматически занимает правильную позицию.
- [ ] Правильно установленная часть ярко подсвечивается зелёным.
- [ ] Установленная часть больше не перемещается.
- [ ] Счётчик увеличивается после каждой правильной установки.
- [ ] Ошибка появляется только при отпускании далеко от силуэта.
- [ ] Страница загружает новую версию кода без старого кеша.
